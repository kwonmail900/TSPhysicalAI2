# ESP32 실물 모형 구성과 시험

이 안내는 **12V 저전압 DC 실습 모형**을 대상으로 합니다. 실제 건물의 AC 분전반이나 태양광·배터리를 연결하지 않습니다. 한 ESP32가 LED 조명과 엔코더 모터를 제어하고 INA260으로 두 부하의 합계 전력을 계측합니다.

## 최소 부품

| 부품 | 수량 | 선정·확인 조건 |
|---|---|---|
| Classic ESP32 WROOM-32 개발 보드 | 1 | 아래 GPIO 핀을 사용할 수 있는 보드 |
| USB 데이터 케이블 | 1 | 펌웨어 업로드와 보드 전원 |
| INA260 전압·전류·전력 센서 보드 | 1 | I²C 논리 전원 3.3V, 고측 전류 계측 |
| 12V LED 모듈 | 1개 이상 | 소비전력과 극성 확인 |
| DFRobot DFR0457 MOSFET 구동기 | 1 | ESP32의 3.3V 제어, LED용 500Hz PWM |
| 12V 엔코더 DC 기어모터 | 1 | 예: Pololu #5219. 회전수·기어비·엔코더 계수 확인 |
| DRV8871 모터 드라이버 보드 | 1 | 모터의 기동·정지 전류와 드라이버 전류 제한 확인 |
| 12V 정전압 전원 어댑터 | 1 | 선택 부하 합계와 기동 전류를 감당하는 용량 |
| 퓨즈·홀더·전원 스위치 | 각 1 | 전원·배선·부하에 맞는 DC 정격 |
| 전원 분기 단자·전력 배선·신호선 | 필요량 | 부하 전력 경로와 GPIO 신호 경로 구분 |
| 고정판·모터 브래킷·회전부 가드 | 필요량 | 실습 중 배선 이탈과 회전부 접촉 방지 |

부품 가격과 재고는 구매 시 확인합니다. 특정 모터 예시의 품번만으로 엔코더 계수나 공급 배선 색상을 가정하지 않습니다. 납품품의 제조사 자료와 커넥터 핀번호를 대조합니다.

## 전력 경로와 공통 접지

```text
12V 어댑터 (+)
    → 퓨즈·전원 스위치
    → INA260 VIN+
    → INA260 VIN−
    → LED 드라이버·모터 드라이버의 부하 전원 (+)

12V 어댑터 (−)
    → 드라이버 GND·ESP32 GND·센서 GND·엔코더 GND

PC USB → ESP32 USB 전원
ESP32 3.3V → INA260 논리 전원·엔코더 논리 전원
```

**INA260의 `VIN−`는 접지가 아니라 전류 센서를 통과한 부하 측 양극입니다.** 이를 GND에 연결하지 마십시오. INA260 보드의 논리 전원 핀과 전류 측정 경로를 구분합니다. 부하 전류는 브레드보드의 얇은 신호 배선을 경유하지 않도록 적절한 배선과 단자를 사용합니다.

모터의 두 전력선은 DRV8871의 두 출력에 연결합니다. 엔코더 전원은 모터의 12V 전원과 별도입니다. 선택 엔코더가 3.3V 동작을 지원하는지 확인하고 ESP32 입력에 12V가 들어가지 않도록 합니다. GPIO는 드라이버의 신호만 전달하며 LED나 모터의 전원을 직접 공급하지 않습니다.

## GPIO 연결

| ESP32 | 연결 대상 | 역할 |
|---|---|---|
| GPIO21 | INA260 SDA | I²C 데이터 |
| GPIO22 | INA260 SCL | I²C 클록 |
| GPIO25 | DFR0457 제어 입력 | LED 500Hz PWM |
| GPIO27 | DRV8871 IN1 | 한 방향 모터 PWM |
| GND | DRV8871 IN2 | 한 방향 구동 기준 |
| GPIO32 | 엔코더 A | 회전 펄스 |
| GPIO33 | 엔코더 B | 방향·회전 펄스 |
| 3.3V | INA260 VCC·지원되는 엔코더 VCC | 논리 전원 |
| GND | 센서·드라이버·엔코더 GND | 노드 공통 기준 |

DRV8871은 H 브리지입니다. 모터를 전원과 저측 스위치 사이에 연결하는 방식과 혼동하지 않습니다. 엔코더 펄스 수가 모터축 기준인지 출력축 기준인지, 한 에지 계수인지 여러 에지 계수인지 확인하여 회전수 환산을 교정합니다.

## 개발 도구와 펌웨어

Arduino IDE와 Espressif의 Arduino-ESP32 **3.x 계열**, Adafruit INA260·BusIO, ArduinoJson **7.x 계열**을 사용합니다. ESP32 3.x의 LEDC 핀 기반 API를 사용하는 코드이므로 오래된 2.x 예제의 채널 초기화 함수를 그대로 섞지 않습니다. 재현 시 실제로 사용한 버전을 기록합니다.

1. `firmware/esp32_node/config.h.example`을 같은 디렉터리의 `config.h`로 복사합니다.
2. Wi-Fi SSID·비밀번호, PC 서버 LAN 주소, 장치 토큰을 로컬 파일에 설정합니다.
3. PC 환경 변수 `TSPAI_DEVICE_TOKEN`과 펌웨어 토큰을 일치시킵니다.
4. Arduino IDE에서 `firmware/esp32_node/esp32_node.ino`를 열고 보드 종류와 포트를 확인하여 전체 스케치를 빌드합니다.
5. 부하 전원을 끈 상태에서 업로드하고, 출력 정지 상태와 센서 연결부터 확인합니다.

`config.h`에는 자격 정보가 있으므로 `.gitignore` 대상으로 유지합니다. 예제 파일에는 실제 비밀번호나 토큰을 넣지 않습니다. PC와 장치의 HTTP 계측·명령 교환은 토큰을 확인하지만, 이 토큰이 로컬 HTTP 통신을 암호화하지는 않습니다.

## 단계별 첫 시험

### 1. 전원 없이 배선 확인

12V 양극과 GND의 단락 여부, INA260 방향, 모터 드라이버 출력, 엔코더 논리 전압, 공통 GND를 확인합니다. 모터와 드라이버를 고정하고 회전부 주변을 정리합니다.

### 2. USB와 센서 시험

부하 출력은 정지 상태로 두고 ESP32를 USB로 켭니다. 센서가 연결되며 PC에 유효한 계측값이 도착하는지 확인합니다. 12V 부하 전원을 연결한 뒤 전압과 무부하 전류가 타당한지 확인합니다.

### 3. LED 단독 계측

가동 승인 후 LED만 단계적으로 켭니다. PWM과 측정 전력의 관계를 기록합니다. 전력계나 멀티미터 등 독립 계기로 가능한 범위에서 대조합니다. PWM 비율이 실제 조도와 선형이라고 가정하지 않습니다.

### 4. 모터 단독 계측

낮은 출력부터 시작하여 기동 가능한 범위를 찾습니다. 실제 회전수, 누적 회전수, 소비전력을 기록하고 엔코더 환산 계수를 점검합니다. 모터 전력은 출력 비율과 기계적 부하에 따라 달라지므로 정격 전력 하나로 작업량을 대신하지 않습니다.

### 5. 통합 운영

동일한 조명 최소 요구와 목표 회전수를 설정하고 예산·시한 조건을 바꿉니다. 제안 출력·실제 적용 출력·측정 전력·작업량을 함께 기록합니다. USB로 공급하는 ESP32 소비전력은 INA260의 부하 합계에 포함하지 않습니다.

## 정지·오류·재가동

| 조건 | 의도한 현장 동작 | 실습에서 확인할 사항 |
|---|---|---|
| 부팅 직후 | 출력 정지 | 자동 가동되지 않는가 |
| 명령 만료 | 출력 정지 | 수신 후 약 1,500ms의 로컬 유효시간을 지키는가 |
| 계측 이상 | 오류 상태로 정지 | 불가능한 값·센서 통신 실패를 감지하는가 |
| 과전류 | 오류 상태로 정지 | 설정 기준과 센서 계측 경계를 이해하는가 |
| 모터 회전 정체 | 엔코더 기반 오류 판단 | 출력 명령과 실제 회전을 구분하는가 |
| 오류 원인 해소 | 오류 해제 후 별도 승인 | 통신 복구만으로 재가동하지 않는가 |

명령 유효시간은 PC와 ESP32의 벽시계 차이가 아니라 장치의 단조 증가 시간을 이용하여 판단합니다. PC 요청이 늦어져도 로컬 정지 처리가 계속 동작하는지 확인합니다. 기본 과전류 기준 2A는 부하·배선·드라이버 정격을 대신하지 않으며, 작은 모터의 정지 전류가 이보다 작을 수 있으므로 **모터 정체는 엔코더 판단과 함께 확인**합니다.

PC는 최근 3초 안의 정상 계측이 있어야 가동을 승인합니다. 장치 재부팅, 계측 순서·경과 시간의 역행, 긴 계측 공백을 처리한 뒤 자동으로 가동을 재개하지 않습니다. 오류 해제 요청 후 장치의 해제 응답을 확인하고, 별도의 가동 승인을 해야 합니다.

에너지는 장치 경과 시간에 따라 측정 전력을 사다리꼴 적분합니다. 계측 간격이 3초를 넘으면 공백을 임의로 보간하지 않고 에너지 유효성과 누락 시간을 기록합니다. USB 전력처럼 계측 경계 밖의 전력이나 통신 공백 구간의 에너지를 이 적분값에 포함했다고 해석하지 않습니다.

모터축을 손으로 잡아 정지시키는 방식으로 시험하지 않습니다. 정체 감지 알고리즘은 우선 시연·호스트 시험으로 확인하고, 실물 오류 시험은 부하 조건과 전류·온도를 검토한 통제된 방식으로 진행합니다.

## 검증 상태를 기록하는 방법

PC 테스트, 호스트에서 컴파일한 C++ 로직, Arduino 전체 보드 빌드, 펌웨어 업로드, 실물 계측은 서로 다른 증거입니다. 아래 항목을 실행 결과와 함께 작성합니다.

```text
보드·드라이버·모터·센서 품번:
Python / Arduino-ESP32 / 센서 라이브러리 버전:
전체 보드 빌드 결과:
업로드 결과:
전압·전류 독립 비교 방법:
엔코더 계수 교정 방법:
명령 만료·오류 해제·재승인 시험 결과:
작업량·서비스 조건을 고정한 반복 운전 결과:
```

실행하지 않은 항목은 미수행으로 기록합니다. PC 모형의 결과를 실제 장치의 성공 결과로 바꾸어 적지 않습니다.
